# Краткое объяснение для защиты

## Лабораторная работа №2

**Что сделано:** создан проект HomeBudget с рабочей консольной программой, README в Markdown и диаграммой вариантов использования. Проект находится в локальном Git-репозитории; коммиты фиксируют отдельные этапы изменений.

**Как показать:**

1. Открыть корень проекта в Visual Studio Code или другой IDE.
2. Открыть `README.md` и показать заголовки, список функций, таблицу технологий и изображения диаграмм.
3. Открыть `diagrams/use_case.puml`: текст описывает акторов «Пользователь» и «Администратор», систему и варианты использования.
4. В терминале выполнить `python src/main.py` и `git log --oneline`.
5. Для отправки на GitHub создать пустой репозиторий в своём аккаунте, добавить его URL как `origin` и выполнить `git push -u origin main`.

**Ключевые понятия:**

- Git — локальная система контроля версий; commit — зафиксированное состояние файлов; branch — отдельная линия разработки.
- GitHub — сервис для размещения удалённого Git-репозитория.
- README.md — главная документация проекта; Markdown — синтаксис разметки текста.
- PlantUML — описание диаграммы текстом; по `.puml` можно повторно визуализировать схему.

## Лабораторная работа №3

**Что сделано:** спроектирована база SQLite из шести таблиц (`users`, `categories`, `products`, `purchases`, `purchase_items`, `expenses`), созданы PK/FK и ограничения, добавлены демонстрационные данные, реализован доступ к данным из Python.

**Как показать:**

1. Открыть `diagrams/er_diagram.png` и исходник `diagrams/er_diagram.puml`.
2. В DB Browser for SQLite или SQLiteStudio открыть `database/homebudget.db` и таблицы.
3. Открыть `database/schema.sql` и показать `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`.
4. Выполнить `python src/main.py products`, затем `python src/main.py purchases` и `python src/main.py expenses`.
5. Выполнить `python -m unittest discover -s tests -v`.

**Как объяснить связи:**

- PK — уникальный идентификатор строки внутри таблицы.
- FK — ссылка на PK другой таблицы; она не даёт сослаться на несуществующую запись.
- `categories` → `products` — 1:N: у категории много продуктов.
- `users` → `purchases` — 1:N: пользователь может оформлять разные покупки.
- `purchases` ↔ `products` — M:N, реализована через `purchase_items`.
- `purchases` → `expenses` — 1:1 в логике приложения; `expenses.purchase_id` уникален.
- SQLite хранит базу в одном файле; транзакция объединяет несколько связанных операций, чтобы ошибка не оставила частично сохранённую покупку.
